# 国服数据引继入口按卡号格式显示（非国服卡不显示该框）

> 轻量任务（frontend-only）。1 个新 lib 判定模块 + 设置页一处条件渲染 + 回归 spec 调整。无新增文案、无后端改动。

## Goal

maimai2 设置页的「国服数据引继」卡片只在**账号默认卡号是国服卡号**时才显示。默认卡是实体 Aime 卡（或没有卡、或旧方案卡号）的账号，整块不渲染，玩家不会再看到一个点了必然失败的按钮。

## Background

- 引继入口把 `defaultCard.luid` 当卡号发给 `lcdx/mergeRegistry/request/{user}/{cardId}`；后端 `TryConvertCardIdToUserId`（`LCDXNetApi/Services/UserService.cs:337`）只接受「20 位 + 前缀 `2430443067` + `(后10位−4579)` 能被 83 整除」，其余一律 `94001 Invalid card id`。
- 前端 `isOk()` 只认 `92001`，于是 `94001` 统一显示为「设置引继请求失败」——**玩家侧看不出是卡号格式问题**。
- 线上实测（2026-10-20，账号 `LCDXDJmYFq`）：`GET lcdx/mergeRegistry/…/50143954486701365311` → `94001`；换成 `24304430670830004579` → `92001`。
- 存量面：`LCDXUserCardPairs` 120 条绑卡记录中，**46 条主卡不是 `2430443067` 前缀**——这些账号的引继按钮当前必然失败。
- 判定规则与后端完全一致即可，无需新端点：卡号格式是稳定契约，前端已有同类镜像先例（`src/lib/botPermission.ts` ↔ 后端 `PermissionLevels.cs`）。

## Requirements

- **R1** 新增框架无关判定模块（`src/lib/`）：入参 20 位卡号字符串，返回布尔。判据镜像后端：
  1. 长度 20 且全为数字；
  2. 前缀 `2430443067`；
  3. `后10位 > 4579` 且 `(后10位 − 4579) % 83 === 0`。
  旧方案 `243044306799` + 8 位原始 id **不予接受**（后端目前也拒；前端不得比后端宽松，否则又会出现「能点但必失败」）。
- **R2** 设置页只在判定为真时渲染「国服数据引继」卡片；为假时整块 **不渲染**（不是 CSS 隐藏、不是禁用按钮）。
- **R3** 保持既有契约不变：绑定卡用 `cards[0].luid`，引继用 `defaultCard.luid`；不新增请求、不改请求路径、不改工具栏其他卡片。
- **R4** 兜底：若判定为真但后端仍回 `94001`（规则漂移），该卡片转为隐藏并停止后续引继交互。
- **R5** 无新增用户可见文案 —— 不新增 i18n key，不动 `zh/en` 四份资源。
- **R6** 同步回归 spec：既有「binding uses the first card while merge uses the default card」用例的默认卡 fixture 必须换成国服卡号，并新增「非国服卡 → 不渲染、且不发 mergeRegistry 请求」的用例。

## Acceptance Criteria

- [ ] 默认卡为国服卡号（如 `24304430670830004579`）→ 卡片显示，状态查询 / 设置 / 取消行为与改造前完全一致
- [ ] 默认卡为实体 Aime 卡（如 `50143954486701365311`）→ 不渲染该卡片，且**不发** `lcdx/mergeRegistry/**` 请求
- [ ] 无卡（`cards: []`）→ 不渲染
- [ ] 旧方案卡号 `243044306799xxxxxxxx` → 不渲染
- [ ] `npm run build`（`tsc -b && vite build`）通过
- [ ] 定向 `tests/lcdx-regression/settings.spec.ts` 全绿（判定方式见 spec：`test-results/lcdx-regression/` 为空 ⇔ 通过）
- [ ] 未改动后端仓库、未改动「绑定卡号」卡片行为

## Out of Scope

- 后端 `TryConvertCardIdToUserId` 增加旧方案（`243044306799`）支持 —— 属 `LCDXNetApi` 独立任务，本任务只保证前端不比后端宽松
- 给被隐藏的账号加「请先绑定国服卡号」提示（需要新文案与新 i18n key，另议）
- 引导玩家获取/绑定国服卡号的流程改造
- 管理后台任何改动

## Notes

- 为什么不是「调后端问一次」：`GET lcdx/mergeRegistry/{user}/{cardId}` 本身能回答（94001 ⇔ 非国服），但它是异步的，用它决定可见性会先闪一下再消失，断网时还会把国服用户的框也藏掉。本地判定同步、无请求、不闪；后端 94001 作为兜底（R4）覆盖规则漂移。
- 判定不接受旧方案是**刻意保守**：宁可让这类账号暂时看不到入口（当前点了也必失败），也不显示一个必然报错的按钮。
- 本任务不 push（push master 会自动部署）；按用户要求边改边提交。
