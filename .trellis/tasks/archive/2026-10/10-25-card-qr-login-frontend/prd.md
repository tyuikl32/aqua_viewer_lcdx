# 卡片页机台登入二维码弹窗

> 复杂任务（frontend-only）。新增 1 个判定扩展 + 1 个弹窗组件 + 卡片页入口 + 12 条文案；并放宽「国服数据引继」入口对旧码卡的判定。后端接口见 `LCDXNetApi` 仓库的同名任务。

## Goal

玩家在「卡片管理」页对**自己的主卡**点一下，就能得到一枚 9 分钟倒计时的机台登入二维码。拿手机对着机台的扫码相机即可登入本人账号，无需实体卡。

## Background

- 后端 `POST lcdx/cardQr/{userName}` 返回 `{ payload, expiresInSeconds: 540 }`，payload 是 40 字符 `NCBTCMDD…`，由游戏侧本地 AES 解密，不联网。
- 卡号有两种形态，**第 11 位**可区分：`'9'` = 旧码 `243044306799` + 8 位 cid；`'0'`/`'1'` = 新码 `2430443067` + `pad10(cid*83+4579)`。合法 cid 区间内新码第 11 位只可能是 `0`/`1`，与旧码互斥（线上 74 条实测零例外）。
- 现有 `isGuofuCardNumber`（`src/lib/guofuCard.ts`）只认新码，旧码返回 false，导致：
  1. 引继入口对旧码卡隐藏（后端当时也只认新码，属刻意保守）；
  2. 本次二维码入口也会对旧码卡隐藏。
  后端同任务已把 `TryConvertCardIdToUserId` 放宽到支持旧码，前端必须同步，否则又出现「能扫不能引继」。
- 应用默认 `colorTheme='auto'`（跟随系统），暗色是主流场景。二维码若不强制白底黑块，机台的 ZXing 解码不保证能反色识别。
- 「10 分钟有效」的精确含义：解码端用机台本地时间往回试 10 个分钟 IV，生成于 `HH:MM:SS` 的码最晚可用到 `HH:MM+9:59`，**最坏 9 分 00 秒**。因此倒计时取 540 秒。

## Requirements

- **R1 判定模块**：`src/lib/guofuCard.ts` 增加 `decodeGuofuCardId(card): number | null`（新码优先、旧码兜底、统一做 cid 区间校验）；`isGuofuCardNumber` 改为「能解出 cid」。
- **R2 引继入口同步放宽**：旧码默认卡也能看到「国服数据引继」卡片；物理卡/无卡仍不渲染。
- **R3 入口**：卡片管理页每个主卡卡片新增二维码按钮，**仅当 `decodeGuofuCardId(card.luid)` 非空**时渲染；别名行不放按钮。
- **R4 弹窗**：标题「机台登入二维码」，展示二维码 + 剩余时间 + 安全警示 + 刷新/保存按钮。
- **R5 二维码渲染**：必须固定白底黑块（与主题解耦）、320px、纠错等级 H、白边 2 模块；渲染失败要有兜底文案。
- **R6 倒计时**：540 秒；归零后清空图像并显示「二维码已失效」，刷新按钮高亮。
- **R7 10 秒冷却**：生成成功后刷新按钮禁用 10 秒并显示剩余秒数，避免用户自己点出 `94032`。冷却状态放在页面级，关闭弹窗不重置。
- **R8 不持久化**：payload 只存在于组件内存，不写 localStorage / sessionStorage / URL / React Query 缓存；关闭弹窗即销毁。
- **R9 竞态**：请求在途时关闭弹窗，响应必须被丢弃（`cancelled` 守卫）。
- **R10 错误映射**：`94001` 卡号不支持、`94031` 非本人卡、`94032` 太频繁、`95001` 暂时无法校验、401 走全局。
- **R11 文案**：新增 `CardsPage.Qr*` 共 12 条，`zh.json` 与 `en.json` 同步。
- **R12 安全警示**：弹窗内固定显示「为了您的账号安全 / 请勿传播此二维码」。

## Acceptance Criteria

- [ ] 新码主卡 → 卡片页出现二维码按钮；点击后展示二维码与 09:00 倒计时
- [ ] 旧码主卡 → 同样出现按钮，且能正常出码
- [ ] 物理卡 / 无卡账号 → 不出现按钮
- [ ] 别名卡行 → 不出现按钮
- [ ] 生成成功后 10 秒内刷新按钮禁用并显示剩余秒数
- [ ] 倒计时归零 → 图像消失且提示「二维码已失效」
- [ ] 后端返回 `94032` → 提示「操作太频繁，请稍后再试」
- [ ] 后端返回 `95001` → 提示「暂时无法校验卡片归属，请稍后重试」
- [ ] 旧码默认卡 → 设置页显示「国服数据引继」入口；物理卡仍隐藏
- [ ] 二维码在暗色主题下仍为白底黑块
- [ ] `npm run build`（`tsc -b && vite build`）通过
- [ ] 定向 `tests/lcdx-regression/settings.spec.ts` 全绿
- [ ] 未改动后端仓库文件

## Out of Scope

- 二维码图片由前端渲染（已有 `qrcode` 依赖），后端只回 payload
- 不做「管理员给任意卡号出码」
- 不做二维码撤销
- 不新增设置页其他入口

## Notes

- 为什么不在前端生成密文：AES 密钥是全局静态值，进前端包等于任何人都能给任意账号造登录凭据。
- 为什么冷却状态放页面级：关闭弹窗再打开若不在同一冷却窗口内，用户会立刻再触发一次 `94032`，体验上像「坏了」。
- 为什么强制白底：应用默认跟随系统暗色，浅色模块画在深底上时机台解码不保证反色成功。
