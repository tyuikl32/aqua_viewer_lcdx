# 玩家二维码独立页面（左侧导航入口）

> 复杂任务（frontend-only）。新增 1 个页面 + 1 条路由 + 1 条侧栏菜单；把二维码从「卡片管理页」和「仪表板」移出，改为独立入口；二维码渲染从模态框重构为可内联面板。

## Goal

玩家能在**左侧导航栏**直接看到「玩家二维码」，点进去就能拿到本人主卡的机台登入二维码。

不再需要知道 `/cards` 这个没有导航入口的页面，也不再挤在仪表板的卡片行里。

## Background

- 上一轮把二维码入口挂在 `/cards`（卡片管理页）。但该页面**全仓没有任何导航指向**（`src/lib/menu.ts` 里没有对应项），只能手敲 URL 才能到达 —— 用户实际看不到入口。用户在仪表板找不到按钮，反馈"我的号为什么也没有"。
- 仪表板当时补了一个按钮，但用户明确要求「单独的一个『玩家二维码』在左侧导航栏，不和 cards 放一起」。
- 侧栏标签来自 `t('App.Sidebar.' + item.name)`（`AppShell.tsx:112`），菜单定义在 `src/lib/menu.ts` 的 `maimai2` 分组。
- 路由挂在 `/mai2` 子路由下（`router.tsx`），页面标题用 `handle.title` 指向 i18n key。
- 现有 `CardQrModal` 把「取码 + 倒计时 + 警示 + 保存/刷新」都写在模态框里，独立页面需要同样的内容但**内联**显示。

## Requirements

- **R1 新页面**：`/mai2/playerqr`，标题「玩家二维码」。
- **R2 侧栏入口**：`maimai2` 分组新增一项「玩家二维码」，登录后可见（`DisplayCondition.AfterLogin`）。
- **R3 内联渲染**：页面进入后直接为可用的主卡渲染二维码（不需要再点一次按钮），并显示倒计时、安全警示、保存图片、刷新。
- **R4 卡片来源**：用 `/api/user/me` 的 `cards[].luid`（主卡），不认别名。每张能解出 cid 的主卡各渲染一块；解不出（物理卡）的不渲染。
- **R5 空状态**：无卡 → 提示绑定卡片；有卡但都不可出码 → 提示卡号不支持。
- **R6 组件拆分**：把二维码主体从 `CardQrModal` 抽成 `CardQrPanel`（内联可用）；删除不再使用的 `CardQrModal` / `CardQrEntry`，避免死代码。
- **R7 移除旧入口**：`CardsPage` 不再渲染二维码入口；`DashboardPage` 不再渲染二维码按钮。
- **R8 不变的行为**：白底黑块（与主题解耦）、540s 倒计时基于服务端 `expiresAt`（缺失回退 `expiresInSeconds`）、10 秒刷新冷却、payload 只存内存、错误码 94001/94031/94032/95001 映射、错误态与二维码互斥。
- **R9 i18n**：新增 `App.Sidebar.PlayerQr` 与 `PlayerQrPage.*`，zh/en 同步。
- **R10 测试**：重写 `cards-qr.spec.ts` 为面向新页面的用例（可出码/物理卡/无卡/频控/暗色像素）。

## Acceptance Criteria

- [ ] 侧栏出现「玩家二维码」，点击进入 `/mai2/playerqr`
- [ ] 2430 主卡账号进入后直接看到二维码 + 倒计时 + 警示文案
- [ ] 物理卡账号进入后看不到二维码，看到「该卡号不支持」提示
- [ ] 无卡账号进入后看到「请先绑定卡片」提示
- [ ] 10 秒内点刷新按钮为禁用并显示倒计时
- [ ] 暗色主题下二维码仍为白底黑块（像素断言）
- [ ] 卡片管理页与仪表板不再出现二维码入口
- [ ] `npm run build` 通过；定向 playwright 全绿
- [ ] 新增文案 zh/en 双份齐全

## Out of Scope

- 不改后端（接口与契约不变）
- 不做多卡切换器（1 人 1 号）
- 不改 `/cards` 页面的其他功能
